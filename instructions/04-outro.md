# Outro

## What you learned

In this lab, you used Copilot Code and Copilot Studio to create separate onboarding checklist apps with fictional data, then previewed, tested, and published them to Copilot Managed Runtime.

- In **Copilot Code**, you added a **New task** modal, updated the app title, and added a completion progress bar. You published the changes and reopened the app to check them.
- In **Copilot Studio**, you created and tested another app, explored device previews, and added a light/dark mode switch.
- In both experiences, you inspected the generated source code without needing to edit it.
- You worked with session-local data, so changes to the checklist may reset when an app is reopened.

Finished early? Feel free to extend your apps or keep exploring how they work.

## Publishing and sharing

This lab focused on **creating and publishing** apps. You did not share your apps with other people.

Publishing makes an app version available through Copilot Managed Runtime. Sharing is a separate step that determines who can use the app, subject to your organization's policies. A link alone does not grant access, and access to an app is distinct from permission to its connected data sources.

## Another way to build apps

Copilot Managed Runtime is in preview. Developers can also use a code-first approach: the **`ms` CLI** (`@microsoft/managed-apps-cli`) helps create, develop, and deploy apps, and the **SDK** (`@microsoft/managed-apps`) provides a client library for interacting with the platform and calling connectors. This is an alternative to the Copilot Code and Copilot Studio experiences you used in the lab.

The CLI/SDK path has its own prerequisites and tenant settings; you did not need to install these tools for this lab.
